# Amazon ML Challenge: Business Entity Resolution
## Solution Documentation: Calibrated Precision-First Cascade (CPFC)

### 1. Executive Summary
This solution implements the **Calibrated Precision-First Cascade (CPFC)** designed specifically around the macro-averaged per-entity $F_{0.5}$ metric with singleton reward. The architecture consists of:
1. **High-Recall Multi-Channel Blocking**: 6 complementary lexical, phonetic, and numeric retrieval channels + S2↔S3 candidate expansion, audited for marginal recall and capped to a strict candidate budget.
2. **Feature Engineering (~150 features)**: Multi-level string similarities (raw, norm, fold, core), unshared/shared rare-token IDF mass, house/unit number conflicts, address tail matching, and open-set country features.
3. **Primary LightGBM Pair Matcher (Stage 2a)**: Trained with 5-fold `GroupKFold` grouped strictly by Source 1 entity, incorporating directional monotone constraints (+1 on similarities, -1 on conflicts) to prevent overfitting to in-distribution noise.
4. **Collective Second-Stage Matcher (Stage 2b)**: Out-of-fold group-context features capturing within-S1 candidate rank, score margins, reverse competition, and sibling support.
5. **Cross-Fitted Isotonic Calibration**: Guarantees raw decision scores represent true posterior probabilities necessary for decision-theoretic set selection.
6. **Soft Exclusivity Enforcement**: Prevents multiple Source 1 entities from competing for the same dirty record, turning S1 deduplication into a structural advantage.
7. **Expected-$F_{0.5}$ Set Selection**: Dynamic programming implementation evaluating candidate prefixes against exact Poisson-binomial true-positive distributions, with $k=0$ corresponding to singleton abstention.

### 2. Multi-Channel Candidate Retrieval & Blocking
| Channel | Key Representation | Retrieval Technique | Failure Mode Addressed |
| :--- | :--- | :--- | :--- |
| **C1 Exact Keys** | `name_core\|\|country`, `name_core\|\|postal`, `name_fold\|\|country` | Hash Inverted Index | Exact matches & suffix differences |
| **C2 Char TF-IDF** | `char_wb` (2,4) n-grams, sublinear TF | Sparse cosine top-K per source | Typos, spacing, abbreviations |
| **C3 Rare Token** | Core tokens with $df \le 50$ | Inverted index ranked by $\sum \text{IDF}$ | Distinctive brand names with noisy tails |
| **C4 Phonetic/Acronym**| `name_fold` rare tokens & initials | Hash index matching | Transliteration variants & acronyms (TCS ↔ Tata Consultancy Services) |
| **C5 Address/Numeric** | Exact `(postal, house_no)` & `(postal, name_core[:3])` | Compound key hash lookup | Rebranded trade names at same location |
| **C6 Sorted Neighbourhood**| Core and reversed core name window $w=10$ | Lexicographic sliding window | Start/end-of-string typos |
| **S2↔S3 Expansion** | Near-duplicate sibling graph ($sim \ge 0.90$) | 1-hop sibling linkage | Dirty-to-dirty cross-reference matching |

### 3. Feature Engineering Summary
- **Name Features**: Levenshtein, Damerau-Levenshtein, Jaro-Winkler, Token Set Ratio, Token Sort Ratio, Soft TF-IDF, Monge-Elkan bidirectional, shared/unshared IDF mass, positional token equality, legal form match/conflict, digit conflict, abbreviation alignment.
- **Address Features**: Full-address similarity, core similarity without landmarks, postal code match/prefix length, house number match and conflict (-1 monotone), unit number match/conflict, digit-set Jaccard, tail segment token overlap, landmark phrase match, address rare-token IDF.
- **Cross-Field & Group Features**: Normalized country equality, name inside opposite address, channel bitmask, per-channel retrieval rank, within-S1 probability rank and margin, reverse rank among competing S1s, candidate set entropy.

### 4. Decision Logic & Metric Alignment
The official $F_{0.5}$ metric is defined as:
$$F_{0.5} = \frac{5 \cdot TP}{4 \cdot |Pred| + |Gold|}$$
- **Break-Even Analysis**:
  - The first candidate vs empty: Break-even is $0.50$ when truth $\in \{c, \emptyset\}$.
  - Additional matches: Break-even increases to $\ge 0.667$.
  - Singletons ($|Gold|=0$): Correct empty prediction yields $1.0$; a single false positive drops the score to $0.0$.
- **Expected-$F_{0.5}$ Set Selection**:
  Computes exact Poisson-binomial distribution of matches inside ($TP_{in}$) and outside ($TP_{out}$) the candidate set, choosing prefix $k^* \in \{0, \dots, K\}$ that maximizes expected $F_{0.5}$. When no candidate crosses the break-even threshold, $k=0$ is chosen, protecting singleton entities.

### 5. Verification & Submission Contract Checks
All submission outputs generated by the cascade are verified against `utils/validate_submission.py`:
- [x] TSV format with explicit `\t` delimiter, `QUOTE_NONE`, and no quotes.
- [x] Header matches exact specification (`source1_entity_id\tmatched_entity_ids` and `source1_entity_id\tcandidate_entity_ids`).
- [x] Exactly one row per test S1 entity in original file order.
- [x] Singletons formatted as empty string `""` (no NaN or null placeholders).
- [x] Every predicted ID exists in the test pool and starts with `S2-` or `S3-`.
- [x] Strict subset contract: $Matches \subseteq Candidates$ for all S1 entities.
